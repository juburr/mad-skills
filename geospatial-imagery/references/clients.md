# Connect imagery to map clients

## Start from the wire request

Capture one real request from the client and compare it with a working
request to the service. Compare version, CRS, axis order, bounding box or
tile matrix IDs, dimensions, and content type. Test a known tile north of
the equator or an asymmetric extent. Check browser CORS and credentials
on the actual imagery and metadata endpoints. Cross-origin pixel reads or
texture uploads require appropriate CORS even when a plain image tag loads.

## CesiumJS

- Use `WebMapServiceImageryProvider` for WMS. Set the version deliberately.
  The pinned provider defaults to WMS 1.1.1. It uses the WMS version and
  configured tiling scheme to choose the default `srs` or `crs`, including
  `CRS:84` for geographic WMS 1.3.0. An explicit `crs` or `srs` must
  agree with the coordinates generated by the tiling scheme.
- For `WebMapTileServiceImageryProvider`, pass the layer, style,
  `tileMatrixSetID`, and matching tiling scheme, tile dimensions, and
  level range. Pass `tileMatrixLabels` when the service uses prefixed
  IDs or a different level-to-ID mapping. Supply the advertised KVP
  endpoint or REST template. Check that the advertised matrix can be
  represented by the chosen tiling scheme.
- For XYZ use `UrlTemplateImageryProvider` with `{z}/{x}/{y}`. For an
  otherwise aligned south-origin grid use `{z}/{x}/{reverseY}`.
  The default geographic scheme starts at 2×1 and the default
  Web Mercator scheme starts at 1×1. Pick the scheme that matches the
  server. For a Tile Map Service XML endpoint, see the provider's
  `fromUrl` API for the version in use.

## OpenLayers

Use `TileWMS` for tiled WMS requests and `ImageWMS` for image requests.
For grid-aligned caching, supply the matching tile grid. The pinned
WMS request helper uses the projection's axis orientation for WMS 1.3.
For WMTS, derive options from the capabilities to preserve the matrix
IDs and grid geometry. The desired layer and matrix set must be advertised.

```js
import WMTSCapabilities from "ol/format/WMTSCapabilities.js";
import WMTS, { optionsFromCapabilities } from "ol/source/WMTS.js";

const capabilities = new WMTSCapabilities().read(capabilitiesXml);
const options = optionsFromCapabilities(capabilities, {
  layer: "ortho",
  matrixSet: "WebMercatorQuad",
});
if (!options || options.matrixSet !== "WebMercatorQuad") {
  throw new Error("Requested imagery layer or grid is unavailable");
}
const source = new WMTS(options);
```

The pinned OpenLayers source percent-encodes values in REST templates, so
a label like `prefix:0` appears as `prefix%3A0` on the wire. Use the decoded
matrix identifier from the server's path parser for lookup.

## Leaflet

Use the XYZ tile layer for a matching grid. Its `tms: true` option
inverts the row on a finite CRS grid. Use the WMS tile layer for
GetMap requests. Verify the map CRS and the WMS layer's CRS and version.
The pinned implementation treats its built-in EPSG:4326 projection as
latitude-first for WMS 1.3.0. Check the emitted BBOX for custom CRSs.
A WMTS URL can be used as an ordinary tile template only when its grid
and matrix IDs map to the client's coordinates. Otherwise, use an
adapter that handles that matrix set.
