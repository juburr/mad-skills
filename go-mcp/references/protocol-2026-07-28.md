# Protocol 2026-07-28 (Stateless MCP)

How the 2026-07-28 MCP specification changes Go servers and clients, and how SDK v1.7.0+ implements it. 2026-07-28 is the SDK's default protocol version; the SDK still speaks 2025-11-25 and older and negotiates per connection.

> Verified against SDK v1.8.0.

## What Changed and What to Do

| Spec change | SDK behavior | Your action |
|---|---|---|
| `initialize` handshake and protocol sessions removed (SEP-2567, SEP-2575) | `Client.Connect` calls `server/discover`, then falls back to `initialize` (capped at 2025-11-25) if the server does not offer 2026-07-28 | None for most code; read client data via request accessors (below) |
| `server/discover` is mandatory | `Server.Connect` registers it, built from `Implementation`, `Instructions`, and capabilities | None |
| Every request carries version, client info, and capabilities in `_meta` | Client injects them; results carry `io.modelcontextprotocol/serverInfo` | Use `req.ProtocolVersion()`, `req.ClientInfo()`, `req.ClientCapabilities()` |
| Server-initiated requests replaced by Multi Round-Trip Requests (SEP-2322) | `InputRequests`/`RequestState`/`InputResponses` fields; client middleware retries automatically; server shim serves legacy clients | Return `InputRequests` instead of calling `Elicit`/`CreateMessage`/`ListRoots` |
| Every result has `resultType` | Set automatically (`complete` / `input_required`) | None |
| GET stream and `resources/subscribe` replaced by `subscriptions/listen` | Client opens listen streams automatically; server APIs unchanged | None |
| `ping`, `logging/setLevel`, `notifications/roots/list_changed` removed | Server answers them with `-32601` on new-protocol requests | Drop `KeepAlive`; set log level per request |
| SSE stream resumability removed | `EventStore` applies only to legacy stateful sessions | Re-issue failed requests; enable `PropagateRequestCancellation` |
| `ttlMs`/`cacheScope` on list and read results (SEP-2549) | Defaults `0` / `"public"`; `ServerOptions.SetCacheable` hook; client-side TTL cache | Set a cache policy; mark per-user results `"private"` |
| `Mcp-Method`, `Mcp-Name`, `Mcp-Param-*` HTTP headers (SEP-2243) | Sent and validated automatically | Optionally annotate tool parameters with `x-mcp-header` |
| Resource-not-found code changed to `-32602` | `ResourceNotFoundError` uses `-32602` (all versions, since v1.7.0) | Update clients matching `-32002` |
| `inputSchema`/`outputSchema` accept any JSON Schema 2020-12; `structuredContent` any JSON value (SEP-2106) | Typed `Out` may be a slice, map, or primitive | None |
| Tasks moved to the `io.modelcontextprotocol/tasks` extension (SEP-2663) | Not implemented by the SDK | Avoid tasks, or implement via custom methods |
| `notifications/elicitation/complete` and `elicitationId` removed | `NotifyElicitationComplete` still exists for legacy sessions | Detect completion on the MRTR retry instead |
| Roots, sampling, logging deprecated (SEP-2577); DCR deprecated in favor of Client ID Metadata Documents; HTTP+SSE transport deprecated | APIs marked `Deprecated:`; still functional | Avoid in new code (see migration paths below) |

## Version Negotiation and Compatibility

| Server transport | 2026-07-28 client | Legacy client (≤ 2025-11-25) |
|---|---|---|
| Stdio, `IOTransport`, in-memory | 2026-07-28 | Full legacy behavior, including the MRTR shim |
| Streamable HTTP, `Stateless: true` | 2026-07-28 | Requests work; no server-to-client requests (MRTR shim fails), no list-changed notifications |
| Streamable HTTP, stateful (default) | Official client falls back to 2025-11-25 automatically | Full legacy behavior |
| SSE (deprecated) | Falls back to 2025-11-25 | Full legacy behavior |

- `mcp.SupportedProtocolVersions()` returns every version the SDK supports, newest first.
- `ServerOptions.SupportedProtocolVersions` narrows what a server offers (it cannot widen it; an unknown version panics in `NewServer`). New-protocol requests at an excluded version get `-32022` with `UnsupportedProtocolVersionData`; a legacy `initialize` is answered with the newest allowed legacy version.
- `ClientSessionOptions.ProtocolVersion` sets the version the client requests first; the server may negotiate another mutually supported version, which `session.InitializeResult().ProtocolVersion` reports.
- A server restricted to 2026-07-28 only cannot run behind a stateful handler — connections fail.

## Stateless HTTP Deployment

`StreamableHTTPOptions.Stateless: true` is the only way to serve 2026-07-28 over HTTP.

- Each HTTP request gets a fresh temporary `ServerSession`; `ServerSession.ID()` is `""` and `ServerOptions.GetSessionID` is ignored.
- GET and DELETE return 405. (`MCPGODEBUG=allowsessionsinstateless=1` restores the pre-v1.7.0 session-header handling until v1.9.0.)
- Any replica can serve any request, including an MRTR retry. A `subscriptions/listen` stream stays pinned to the replica that accepted it, and only that replica's `Server` mutations (e.g., `AddTool`) notify it.
- Keep cross-call state out of process memory: mint opaque handles (IDs, cursors) in tool results and accept them as tool arguments, or put request-scoped progress in `RequestState`.
- `PropagateRequestCancellation: true` cancels the handler context when the client closes the response stream, which the spec defines as cancellation.
- `auth.TokenInfo.UserID` session binding only applies to stateful sessions; authenticate every request with `auth.RequireBearerToken`.

## Per-Request Metadata

| Constant | Wire key | Accessor on `ServerRequest[P]` |
|---|---|---|
| `mcp.MetaKeyProtocolVersion` | `io.modelcontextprotocol/protocolVersion` | `ProtocolVersion()` |
| `mcp.MetaKeyClientCapabilities` | `io.modelcontextprotocol/clientCapabilities` | `ClientCapabilities()` |
| `mcp.MetaKeyClientInfo` | `io.modelcontextprotocol/clientInfo` | `ClientInfo()` |
| `mcp.MetaKeyLogLevel` (deprecated) | `io.modelcontextprotocol/logLevel` | — (used by `ServerSession.Log`) |
| `mcp.MetaKeyServerInfo` | `io.modelcontextprotocol/serverInfo` | — (set on results) |
| `mcp.MetaKeySubscriptionID` | `io.modelcontextprotocol/subscriptionId` | — (set on listen notifications) |

The accessors fall back to the `initialize` data on legacy sessions, so use them unconditionally. On 2026-07-28 sessions `ServerSession.InitializeParams()` is synthesized from the first request's `_meta`, and `ServerOptions.InitializedHandler` is never called.

## Multi Round-Trip Requests in Depth

### Server Rules

- Return `InputRequests` from `tools/call`, `prompts/get`, or `resources/read` handlers only.
- Choose map keys freely; they must be unique within the result. The retry echoes them in `InputResponses`.
- Never combine `InputRequests` with content: `Content` or `StructuredContent` on tool results, `Messages` on prompt results, or `Contents` on resource results. The SDK returns `-32603`. The typed `AddTool` wrapper discards a typed handler's output on input-required rounds rather than failing, so return the zero value there to avoid confusion.
- Include only request types the client declared in `req.ClientCapabilities()` (e.g., a non-nil `Sampling`; `Sampling.Tools` as well for tool-enabled sampling, because a client with only a basic `CreateMessageHandler` silently drops `Tools`/`ToolChoice`; `Sampling.Context` for `IncludeContext` other than `"none"`; for form elicitation, a non-nil `Elicitation.Form`, or `Elicitation` with both `Form` and `URL` nil, which older clients send to mean form). To reject a client that lacks one, return a `*jsonrpc.Error` with `Code: mcp.CodeMissingRequiredClientCapabilities` and `Data` set to the JSON encoding of `mcp.MissingRequiredClientCapabilityData{RequiredCapabilities: ...}`.
- Do not assume the client retries. A server may return input requests again on the retry (e.g., to re-prompt after an invalid answer), but only for clients that run the retry loop themselves: gate re-prompting on `req.ProtocolVersion() >= "2026-07-28"`. The legacy shim (below) runs a single round, so a second round reaches other legacy clients as an empty successful result.
- **Load shedding:** return a non-nil empty `mcp.InputRequestMap{}` (optionally with `RequestState`) to make the client retry later. The SDK client gives up at the third load-shedding result (retrying immediately, without backoff) or after 10 rounds overall; legacy clients get a "server is busy" error instead.

### Protecting `RequestState`

`RequestState` round-trips through the client, so treat it as attacker-controlled. When it influences authorization, resource access, or business logic, integrity-protect it and bind it to the principal, the originating request, and a short expiry. Enforce single use server-side when replay matters (e.g., one-time redemptions).

```go
type pendingState struct {
    Subject string    `json:"sub"`
    Tool    string    `json:"tool"`
    ArgsSum string    `json:"args"` // digest of the salient arguments
    Step    int       `json:"step"`
    Expires time.Time `json:"exp"`
}

func sealState(key []byte, s pendingState) (string, error) {
    payload, err := json.Marshal(s)
    if err != nil {
        return "", err
    }
    mac := hmac.New(sha256.New, key)
    mac.Write(payload)
    return base64.RawURLEncoding.EncodeToString(payload) + "." +
        base64.RawURLEncoding.EncodeToString(mac.Sum(nil)), nil
}

func openState(key []byte, token, subject, tool, argsSum string) (pendingState, error) {
    var s pendingState
    payloadB64, sigB64, ok := strings.Cut(token, ".")
    if !ok {
        return s, errors.New("malformed request state")
    }
    payload, err := base64.RawURLEncoding.DecodeString(payloadB64)
    if err != nil {
        return s, err
    }
    sig, err := base64.RawURLEncoding.DecodeString(sigB64)
    if err != nil {
        return s, err
    }
    mac := hmac.New(sha256.New, key)
    mac.Write(payload)
    if !hmac.Equal(sig, mac.Sum(nil)) {
        return s, errors.New("request state signature mismatch")
    }
    if err := json.Unmarshal(payload, &s); err != nil {
        return s, err
    }
    if s.Subject != subject || s.Tool != tool || s.ArgsSum != argsSum || time.Now().After(s.Expires) {
        return s, errors.New("request state rejected")
    }
    return s, nil
}
```

Use AEAD (e.g., `crypto/cipher` AES-GCM) instead of HMAC when the state must also stay confidential.

### Legacy Clients

`serverMultiRoundTripMiddleware` is installed automatically. For a client below 2026-07-28 it intercepts the `InputRequests`, fulfils them with `ServerSession.Elicit`, `CreateMessageWithTools`, or `ListRoots`, and re-invokes the handler exactly once with `InputResponses` and `RequestState` set. This requires a bidirectional session: it fails over stateless HTTP and when the client lacks the capability. If the re-invoked handler returns `InputRequests` again, the shim passes that result through unfulfilled: a legacy client that does not run the MRTR loop itself sees `content: []` and treats the call as succeeded. (Go SDK clients run the loop on every version, so they mask this in Go-only tests.) Collect everything a legacy client must answer in one round.

### Client Side

The default `clientMultiRoundTripMiddleware` fulfils requests concurrently using `ClientOptions.ElicitationHandler`, `CreateMessageHandler`/`CreateMessageWithToolsHandler`, and the client's roots, then retries with a new request ID. The caller sees only the final result. It never mutates the caller's params.

To handle rounds yourself (e.g., to show a custom UI between rounds), disable it:

```go
client := mcp.NewClient(impl, &mcp.ClientOptions{
    MultiRoundTrip: &mcp.MultiRoundTripOptions{Disabled: true},
    // No ElicitationHandler here, so declare the capability explicitly;
    // otherwise servers that check capabilities never send the request.
    Capabilities: &mcp.ClientCapabilities{
        Elicitation: &mcp.ElicitationCapabilities{Form: &mcp.FormElicitationCapabilities{}},
    },
})
// ...
const (
    maxRounds = 10 // the SDK's built-in middleware uses the same caps
    maxShed   = 3  // give up at the third load-shedding result
)

params := &mcp.CallToolParams{
    Name:      "deploy",
    Arguments: map[string]any{"env": "prod"},
}
res, err := session.CallTool(ctx, params)
shed := 0
for round := 1; err == nil && res.NeedsInput(); round++ {
    if round >= maxRounds {
        return errors.New("deploy: too many input rounds")
    }
    if len(res.InputRequests) == 0 { // load shedding: the server is busy
        if shed++; shed >= maxShed {
            return errors.New("deploy: server busy")
        }
        select { // back off before retrying instead of adding load
        case <-time.After(time.Duration(shed) * time.Second):
        case <-ctx.Done():
            return ctx.Err()
        }
    }
    responses := mcp.InputResponseMap{}
    for id, ir := range res.InputRequests {
        p, ok := ir.(*mcp.ElicitParams)
        if !ok { // never send a partial retry; this client only declared elicitation
            return fmt.Errorf("deploy: unsupported input request %T", ir)
        }
        responses[id] = askUser(p) // returns *mcp.ElicitResult
    }
    retry := *params // keep Name, Arguments, and Meta from the original call
    retry.InputResponses = responses
    retry.RequestState = res.RequestState // echo exactly; never inspect
    res, err = session.CallTool(ctx, &retry)
}
if err != nil { // the loop also exits on an RPC error from the first call or a retry
    return err
}
// res is the final, complete result
```

Retry the original request — same arguments and `_meta` — with only `InputResponses` and `RequestState` added; the retry gets a new JSON-RPC ID automatically. Copy the params instead of mutating them so a reused params value never carries one call's responses into the next.

`GetPromptResult` and `ReadResourceResult` expose the same `NeedsInput()`, `InputRequests`, and `RequestState`; `GetPromptParams` and `ReadResourceParams` accept `InputResponses` and `RequestState`.

### URL-Mode Elicitation

Return `&mcp.ElicitParams{Message: ..., URL: consentURL}` (mode is inferred from `URL`; the client must declare `Elicitation.URL`). The client's handler opens the URL and returns. On the retry, check whether the out-of-band flow finished (keyed by an ID you carry in `RequestState`); if not, return the input request again.

## Subscriptions (`subscriptions/listen`)

- **List changes:** `Client.Connect` opens one listen stream when `ToolListChangedHandler`, `PromptListChangedHandler`, or `ResourceListChangedHandler` is set and the server advertises `listChanged` for that kind.
- **Resource updates:** `ClientSession.Subscribe` opens a listen stream for the URI; `Unsubscribe` cancels it (idempotent). `ClientOptions.ResourceUpdatedHandler` receives the notifications.
- **Server side:** unchanged. Adding or removing features notifies listeners; `Server.ResourceUpdated` notifies subscribers; `SubscribeHandler`/`UnsubscribeHandler` still fire.
- Capabilities are inferred from features registered before `Server.Connect`. A server that registers features later must declare them in `ServerOptions.Capabilities` or clients never subscribe.
- Request-scoped notifications (progress, log messages) still flow on the originating request's response stream, not the listen stream.

## Result Caching

`ListToolsResult`, `ListPromptsResult`, `ListResourcesResult`, `ListResourceTemplatesResult`, `ReadResourceResult`, and `DiscoverResult` embed `mcp.Cacheable{TTLMs int; CacheScope string}`.

- The SDK defaults `CacheScope` to `"public"` and builds list results with `TTLMs: 0` (immediately stale).
- A `ResourceHandler` may set `Cacheable` on its `ReadResourceResult`; the SDK keeps it.
- `ServerOptions.SetCacheable` runs after every such handler and may adjust the values:

```go
server := mcp.NewServer(impl, &mcp.ServerOptions{
    SetCacheable: func(_ context.Context, req mcp.Request, c *mcp.Cacheable) {
        switch req.(type) {
        case *mcp.ListToolsRequest, *mcp.ListPromptsRequest:
            // Allowlist: this server's tool and prompt catalogs are static and
            // identical for every caller, so any client or intermediary may cache them.
            c.TTLMs, c.CacheScope = 300_000, "public"
        default:
            // Everything else may depend on the caller (bearer token, mTLS identity,
            // cookie, tenant) or change at any time. Keep the handler's choice,
            // which is ttlMs 0 unless the handler opted in.
        }
    },
})
```

Grant a positive TTL only through an explicit allowlist of results you know are identical for every caller. A missing `TokenInfo` does not prove a result is public — the caller may be identified by mTLS, a cookie, or a header. A per-tenant tool set (a different `*Server` per tenant) is identity-dependent too. A `ResourceHandler` that opts into a positive TTL for per-user data must also set `CacheScope: "private"`.

`SetCacheable` may run with the server lock held: never add or remove features or range over `Server.Sessions()` inside it.

On 2026-07-28 sessions `ClientSession.ListTools`/`ListPrompts`/`ListResources`/`ListResourceTemplates`/`ReadResource` (and the iterators built on them) serve cached results until the TTL expires. List-changed and resource-updated notifications invalidate the cache. The cache belongs to the `ClientSession` and is keyed only by cursor or URI, not by caller — so `"private"` does not stop a session shared across users (e.g., with a rotating bearer token) from serving one user's cached result to another. Use one session per principal, or have the server keep per-user results at `ttlMs: 0`.

## HTTP Header Mirroring

| Header | Mirrors | Mismatch |
|---|---|---|
| `Mcp-Protocol-Version` | `_meta` protocol version | `-32020` |
| `Mcp-Method` | JSON-RPC `method` | `-32020` |
| `Mcp-Name` | `params.name` (`tools/call`, `prompts/get`) or `params.uri` (`resources/read`) | `-32020` |
| `Mcp-Param-{Name}` | A tool argument annotated with `x-mcp-header` | `-32020` |

Gateways and load balancers can route or rate-limit on these without parsing bodies. To expose a tool argument as a header, annotate its schema property. Keep the typed handler by customizing the inferred schema:

```go
type QueryInput struct {
    Region string `json:"region" jsonschema:"cloud region"`
    Query  string `json:"query"`
}

in, err := jsonschema.For[QueryInput](nil)
if err != nil {
    log.Fatal(err)
}
in.Properties["region"].Extra = map[string]any{"x-mcp-header": "Region"}
mcp.AddTool(server, &mcp.Tool{Name: "query", InputSchema: in}, queryHandler)
// Clients send "Mcp-Param-Region: eu-west1"; handlers can read req.Extra.Header.
```

- Annotated properties must be `string`, `integer`, or `boolean`; tools with invalid annotations are silently dropped from `tools/list`.
- The client learns annotations from `tools/list`. The v1.8.0 client does not re-list automatically, so a call made before listing tools is rejected for a missing header — list tools first (the spec says to re-list and retry on a header mismatch).
- Non-ASCII values are sent Base64-encoded (`=?base64?...?=`).

## Error Codes

| Constant | Code | Meaning |
|---|---|---|
| `mcp.CodeHeaderMismatch` | `-32020` | HTTP header disagrees with the body (was `-32001` in v1.6.x) |
| `mcp.CodeMissingRequiredClientCapabilities` | `-32021` | Server needs a capability the client did not declare; data: `MissingRequiredClientCapabilityData` |
| `mcp.CodeUnsupportedProtocolVersion` | `-32022` | Version not supported; data: `UnsupportedProtocolVersionData{Supported, Requested}` |
| `jsonrpc.CodeInvalidParams` | `-32602` | Also used for resource not found (`mcp.CodeResourceNotFound` is deprecated) |
| `jsonrpc.CodeMethodNotFound` | `-32601` | Also returned for removed methods (`ping`, `logging/setLevel`) on new-protocol requests |

The spec reserves `-32020` to `-32099` for MCP; `-32000` to `-32019` remain implementation-defined.

## Deprecated Features and Migration Paths

| Feature | Instead |
|---|---|
| Roots (`Client.AddRoots`, `ServerSession.ListRoots`, `ListRootsParams`) | Take paths as tool arguments, resource URIs, or server configuration |
| Sampling (`CreateMessageHandler`, `ServerSession.CreateMessage*`) | Call the LLM provider API from the server |
| Logging (`NewLoggingHandler`, `ServerSession.Log`, `SetLoggingLevel`) | stderr for stdio servers; OpenTelemetry for observability |
| HTTP+SSE transport (`NewSSEHandler`, `SSEClientTransport`) | Streamable HTTP |
| Dynamic Client Registration (`DynamicClientRegistrationConfig`) | `ClientIDMetadataDocumentConfig` |
| `includeContext: "thisServer"`/`"allServers"` | Omit or use `"none"` |

Deprecated features remain functional for at least twelve months after 2026-07-28.

## Server Migration Checklist

1. Upgrade to `github.com/modelcontextprotocol/go-sdk/mcp@v1.8.0`.
2. Serve HTTP with `Stateless: true` and `PropagateRequestCancellation: true`; move any per-session state into handles or `RequestState`.
3. Replace `req.Session.Elicit`/`CreateMessage`/`ListRoots` calls with returned `InputRequests`.
4. Remove reliance on `KeepAlive`, `InitializedHandler`, `Ping`, and `SetLoggingLevel`.
5. Read client identity and capabilities through `req.ClientInfo()` / `req.ClientCapabilities()`.
6. Set a `SetCacheable` policy (mark per-user results `"private"`).
7. Update clients and tests that match on `-32002`, `-32001`, or a non-zero `ReadOnlyHint`/`IdempotentHint` omission.
8. Test both protocol eras: the in-memory default (2026-07-28) and a client requesting `&mcp.ClientSessionOptions{ProtocolVersion: "2025-11-25"}`, asserting `session.InitializeResult().ProtocolVersion` in each.
